You are a Senior Industrial IoT Architect, Senior .NET Engineer,
Senior Next.js Engineer, and IoT Protocol Engineer.

I want to build a complete production-like Industrial IoT Monitoring
Platform from scratch as a serious software engineering learning project.

The goal is to prepare me for a Software Engineer / IoT Software Engineer
role where I may work with devices, telemetry, MQTT, protocols,
backend services, databases, real-time systems, dashboards,

Build the project as a realistic but manageable IoT platform.

microservices, Redis, etc. unless a real requirement demonstrates why
they are needed.

============================================================

Do not mix these concepts.

- MQTT connection
- TCP connection
- HTTP connection


Protocol examples:

- MQTT
- Proprietary TCP protocol
- BACnet

- Vendor-specific protocol


Payload format examples:

- JSON
- HEX
- Binary
- Proprietary


Payload mapping:

Different devices and vendors may send completely different
JSON structures even when they use the same MQTT topic.


All external device data must eventually become:

NormalizedTelemetry


The rest of the application must work with the normalized internal model
instead of understanding every vendor's format.

13. MULTIPLE JSON STRUCTURES
============================================================

THIS IS A CRITICAL REQUIREMENT.


Different devices can send different JSON structures through the
same MQTT telemetry topic.


Example topic:

iot/tenant-001/site-001/device-001/telemetry


Vendor A:

{
  "deviceId": "D001",
  "temp": 31.5,
  "hum": 68
}


Vendor B:

{
  "device": "D001",
  "temperature": 31.5,
  "humidity": 68
}


Vendor C:

{
  "id": "D001",
  "data": {
    "temperature": 31.5,
    "humidity": 68
  }
}


Vendor D:

{
  "device_id": "D001",
  "temperature_c": 31.5,
  "humidity_percent": 68
}


All must become:

NormalizedTelemetry


DO NOT solve this by creating different MQTT topics.
